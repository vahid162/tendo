# مقایسهٔ تغییرات حرکت چشم همکار

این شاخه یک آزمایش برای مشاهده است؛ هنوز برای PR، مرج یا انتشار تأیید نشده.

## دقیقاً چه چیزی تغییر کرده؟

- پایه: `feature/web-preview` در commit `b5906aa2d3093698df8d6bf2a38076c68437930c`.
- شاخهٔ آزمایش: `experiment/colleague-eye-motion`.
- فایل دریافت‌شده: `sketch.ino`، نسخهٔ درج‌شدهٔ `0.10.0-rc.8`.
- SHA-256 فایل اصلی دریافت‌شده: `8efabf59b92936a9b51ed6a4a90d979e84420d93de0ba64e1f98f5763a948fc7`.
- مبنای تاریخی فایل: `cf76a1c:simulator/wokwi/sketch.ino`.

فایل دریافت‌شده نسبت به مبنای تاریخی فقط سه قسمت تغییر دارد. نسخهٔ اولیهٔ
هر سه تابع با تابع ماژولار فعلی یکسان است؛ بنابراین نسخهٔ ویرایش‌شدهٔ همان
سه تابع، عیناً در `firmware/tando_final_demo_15min/Eyes.cpp` قرار گرفته است:

1. هدف‌های `chooseIdleLook()` به دامنهٔ افقی تا ±30 و عمودی از -24 تا +14 تغییر کرده‌اند.
2. در `updateEyeTargets()` بعد از محاسبهٔ Autonomous، X در 1.3 و فقط Y منفی در 1.4 ضرب می‌شود.
3. در `updateEyeDynamics()` مقدار `gazeSpeed` از 5.4 به 8 تغییر کرده است.

این مقایسه، «تغییر حرکت همکار روی پایهٔ فعلی» است. کل فریم‌ور قدیمی RC8،
پیکربندی انتقال SPI یا فاصلهٔ فریم قدیمی آن جایگزین پایه نشده است. هدف فریم
مرورگر برای هر دو نسخه همان ۱۶ میلی‌ثانیه است. شمارهٔ نسخهٔ فریم‌ور همچنان
RC18 می‌ماند و نام شاخه، آزمایش را مشخص می‌کند؛ Release تازه‌ای ساخته نمی‌شود.

## دو نسخه را هم‌زمان اجرا کن

دو branch در یک پوشه برای اجرای هم‌زمان کافی نیستند؛ تغییر checkout آن پوشه
می‌تواند ورودی سرور روشن را عوض کند. از دو پوشهٔ کاری مستقل استفاده کن:

| نسخه | پوشهٔ نمونه | آدرس |
|---|---|---|
| پایهٔ فعلی | `tendo` روی `feature/web-preview` | `http://127.0.0.1:8787/` |
| حرکت همکار | `tendo-colleague-eyes` روی شاخهٔ آزمایش | `http://127.0.0.1:8788/` |

سرور فعلی را در ترمینال اول روشن نگه دار. برای دریافت آزمایش، در ترمینال دوم
**از روت همان ریپوی اصلی** که نصب Wokwi آماده دارد اجرا کن:

```powershell
git remote set-branches --add origin experiment/colleague-eye-motion
git fetch origin
git worktree add --track -b experiment/colleague-eye-motion ..\tendo-colleague-eyes origin/experiment/colleague-eye-motion
& .\simulator\wokwi\.venv\Scripts\python.exe ..\tendo-colleague-eyes\simulator\web\run.py --port 8788 --gfx-dir '.\simulator\wokwi\.pio\libdeps\tando-s3-sim\Adafruit GFX Library'
```

فرمان `worktree add` فقط بار اول لازم است. اگر همین پوشه و شاخه را قبلاً
ساخته‌ای، دوباره آن فرمان را نزن؛ برای اجرای دوباره فقط فرمان آخر را از روت
ریپوی اصلی اجرا کن. اگر نام/مسیر از قبل برای کار دیگری استفاده شده، مسیر
آزمایش دیگری انتخاب کن و پوشهٔ موجود را پاک یا overwrite نکن.

در پوشهٔ دوم، venv و کتابخانهٔ دانلودشده کپی نمی‌شوند. فرمان بالا Python و
GFX نصب موجود را دوباره استفاده می‌کند؛ `run.py` منبع و خروجی ساخت را از
پوشهٔ آزمایش می‌گیرد. برای پیش‌نیازهای مستقل یا SDK با مسیر متفاوت،
[راهنمای وب](../README.md) را دنبال کن و مسیر SDK/GFX خودت را بده.

دو آدرس را در **دو پنجرهٔ مرورگر کنار هم** باز کن. دو تب در یک پنجره برای
مقایسهٔ زنده مناسب نیستند، چون پیش‌نمایش در تب مخفی مکث می‌کند.

- نام شاخهٔ هر پنجره را بررسی کن؛ شمارهٔ فریم‌ور برای هر دو RC18 است.
- هر دو از C++ مشترک ساخته شده‌اند؛ فقط سه تغییر بالا متفاوت‌اند.
- از دکمه‌های یکسان مثل پلک، نگاه، نوازش و غذا برای مقایسه استفاده کن.
- حرکت خودکار تصادفی است؛ زمان شروع و حالت خودکار دو پنجره الزاماً یکسان نیست.
- دادهٔ پیشرفت هر شاخه/پورت جداست. حفظ پیشرفت قبلی با اجرای تازه از صفر فرق دارد؛
  دستور پاک‌کردن داده در راهنمای اصلی وب آمده است.
- صرف بازشدن صفحه یا سرعت هدف ۱۶ میلی‌ثانیه، تأیید بهترشدن ظاهر یا عملکرد برد نیست.

برای توقف نسخهٔ آزمایش `Ctrl+C` را در ترمینال دوم بزن. فایل‌ها و سرور نسخهٔ
پایه دست‌نخورده می‌مانند. نتیجهٔ ردشده می‌تواند روی همین شاخه بماند؛ حذف شاخه
یا reset نسخهٔ پایه لازم نیست. PR فقط پس از تأیید نتیجه توسط مالک پروژه و
بررسی‌های مربوط به ESP32 آماده می‌شود.
