# پیش‌نمایش وب تندو

این مسیر برای طراحی حرکت، ظاهر و واکنش چشم‌ها با C++ است. همان منبع اصلی
فریم‌ور در مرورگر اجرا می‌شود؛ تغییر پذیرفته‌شده را لازم نیست به زبان دیگری
تبدیل یا دستی به پوشهٔ برد منتقل کنیم.

## هر بخش چه کاری می‌کند؟

| بخش | نقش | محل تغییر |
|---|---|---|
| C++ اصلی | رسم و حرکت چشم‌ها، واکنش‌ها و منطق Demo | `firmware/tando_final_demo_15min/` |
| WebAssembly یا WASM | خروجی کامپایل C++ که مرورگر اجرا می‌کند | تولیدشده در `.build/preview.wasm`؛ ویرایش نمی‌شود |
| HTML، CSS و JavaScript | صفحه، دکمه‌ها، نمایش بافر تصویر و اتصال به C++ | `simulator/web/ui/` |
| آداپترهای C++ | جایگزین امکانات Arduino، نمایشگر و ذخیره‌سازی در مرورگر | `simulator/web/adapters/` و `wrapper.cpp` |
| Python | کامپایل با `build.py` و سرور محلی با `run.py` | `simulator/web/` |

منطق چشم‌ها در JavaScript بازنویسی نشده است. `simulator/wokwi/` مسیر مستقل
شبیه‌سازی ESP32 در Wokwi است؛ برای استفاده از وب، فایل‌های اختصاصی Wokwi و
VS Code را تغییر نده.

## دریافت کد و انتخاب شاخه

زیرساخت وب فعلاً در شاخهٔ `feature/web-preview` برای بازبینی قرار دارد؛ هنوز
نباید وجود آن را در `main` یا `develop` فرض کرد. پس از تأیید و مرج، مبنای
توسعه به `develop` برمی‌گردد.

برای دریافت تازه، ابتدا [Git](https://git-scm.com/downloads) را نصب کن و در
ترمینال پوشه‌ای که می‌خواهی ریپو در آن ساخته شود اجرا کن:

```powershell
git clone --branch feature/web-preview https://github.com/vahid162/tendo.git tendo-web
cd tendo-web
```

اگر قبلاً ریپو را با نصاب Wokwi گرفته‌ای، در همان ریپو اجرا کن:

```powershell
git status --short
git remote set-branches --add origin feature/web-preview
git fetch origin
git switch feature/web-preview
```

خروجی `git status --short` را قبل از تغییر شاخه بررسی و تغییرات ذخیره‌نشدهٔ
خودت را نگه‌داری کن. اگر Git از جابه‌جایی جلوگیری کرد، از `--force` یا
`reset --hard` استفاده نکن؛ ابتدا کار خودت را ذخیره کن یا clone جدا بگیر.

نصاب قبلی با `--single-branch` فقط یک شاخه را دریافت می‌کرد. فرمان
`remote set-branches --add` دریافت شاخهٔ وب را هم فعال می‌کند و شاخهٔ قبلی را
نگه می‌دارد. `git switch feature/web-preview` هم برای بار اول و هم در اجرای
دوباره قابل استفاده است.

برای گرفتن تغییرات بعدی، وقتی روی همین شاخه هستی و کار ذخیره‌نشده نداری:

```powershell
git pull --ff-only origin feature/web-preview
```

از اینجا به بعد، محل اجرای فرمان‌ها **روت ریپو** است؛ پوشه‌ای که `VERSION`،
`firmware/` و `simulator/` داخل آن‌اند. اگر اکنون در `simulator/wokwi` هستی،
با `cd ../..` به روت برگرد.

## پیش‌نیازها و نصب از صفر

برای اجرای وب به Python 3.9 یا جدیدتر، WASI SDK، Adafruit GFX 1.13.0 و مرورگر
جدید مثل Chrome، Edge یا Firefox نیاز داری. Node و Playwright فقط برای
بررسی‌های اختیاری توسعه‌اند. نصب VS Code، افزونه یا توکن Wokwi شرط اجرای وب نیست.

### اگر نصب Wokwi را از قبل داری

می‌توانی از Python موجود در `simulator/wokwi/.venv/` استفاده کنی. ابزار SDK را
در `$env:USERPROFILE\.wokwi\wasi-sdk` و کتابخانه را در
`simulator/wokwi/.pio/libdeps/tando-s3-sim/Adafruit GFX Library` پیدا می‌کند.
اگر این فایل‌ها موجود و نسخهٔ کتابخانه درست‌اند، به بخش اجرا برو.

استفاده از Python این پوشه فقط اجرای ابزار استاندارد Python است؛ بسته، تنظیم
یا فایلی در مسیر Wokwi تغییر نمی‌کند. `run.py` چیزی دانلود یا نصب نمی‌کند.

### نصب مستقل در ویندوز

1. [Python](https://www.python.org/downloads/) نسخهٔ 3.9 یا جدیدتر را نصب کن.
   در PowerShell با `py -3 --version` نصب را بررسی کن.
2. از [انتشار رسمی WASI SDK 25](https://github.com/WebAssembly/wasi-sdk/releases/tag/wasi-sdk-25)
   بستهٔ کامل مناسب سیستم را بگیر. برای ویندوز x64، نام آن
   `wasi-sdk-25.0-x86_64-windows.tar.gz` است. بسته‌های `wasi-sysroot` یا
   `libclang_rt` به‌تنهایی SDK کامل نیستند.
3. بسته را استخراج کن. برای مثال، پوشهٔ استخراج‌شده را در `C:\tools\wasi-sdk`
   بگذار؛ خود این پوشه باید `bin\clang++.exe` و `share\wasi-sysroot` داشته باشد.
   مسیر واقعی سیستم خودت را در فرمان زیر قرار بده.
4. کتابخانهٔ نسخهٔ دقیق 1.13.0 را با فرمان‌های زیر در بیرون ریپو دریافت کن:

```powershell
New-Item -ItemType Directory -Force "$env:USERPROFILE\Tando-Tools" | Out-Null
git clone --branch 1.13.0 --depth 1 https://github.com/adafruit/Adafruit-GFX-Library.git "$env:USERPROFILE\Tando-Tools\Adafruit-GFX-Library-1.13.0"
$env:WASI_SDK_PATH = 'C:\tools\wasi-sdk'
$env:TANDO_WEB_GFX_DIR = "$env:USERPROFILE\Tando-Tools\Adafruit-GFX-Library-1.13.0"
```

پیام Git دربارهٔ `detached HEAD` در clone کتابخانهٔ یک tag طبیعی است؛ فایل‌های
کتابخانه را ویرایش نکن. ساخت، هش چهار فایل GFX را با `gfx.sha256` بررسی می‌کند.

متغیرهای بالا فقط برای همان ترمینال‌اند؛ در ترمینال تازه دوباره مقدارشان را
تنظیم کن. به‌جای آن‌ها می‌توان مسیرها را در هر اجرا صریح داد:

```powershell
py -3 .\simulator\web\run.py --wasi-sdk 'C:\tools\wasi-sdk' --gfx-dir "$env:USERPROFILE\Tando-Tools\Adafruit-GFX-Library-1.13.0"
```

در لینوکس و macOS نیز بستهٔ SDK مناسب سیستم را از همان انتشار بگیر، GFX 1.13.0
را دریافت کن و از روت ریپو اجرا کن:

```bash
python3 simulator/web/run.py --wasi-sdk /path/to/wasi-sdk --gfx-dir /path/to/Adafruit-GFX-Library-1.13.0
```

مسیر SDK باید پوشهٔ حاوی `bin/clang++` و `share/wasi-sysroot` باشد. مسیر GFX
پوشهٔ حاوی `Adafruit_GFX.cpp`، `Adafruit_GFX.h`، `glcdfont.c` و `gfxfont.h` است.

## اجرا و استفاده از صفحه

با Python نصب‌شدهٔ Wokwi، از روت ریپو:

```powershell
& .\simulator\wokwi\.venv\Scripts\python.exe .\simulator\web\run.py
```

یا با Python مستقل، پس از معرفی مسیر پیش‌نیازها:

```powershell
py -3 .\simulator\web\run.py
```

فرمان، C++ را می‌سازد و مرورگر را در `http://127.0.0.1:8787/` باز می‌کند.
اگر مرورگر خودکار باز نشد، همین آدرس را دستی باز کن. ترمینال باز بماند؛
`Ctrl+C` سرور را متوقف می‌کند. برای اجرای دوباره همان فرمان را بزن.

صفحه باید دو چشم، نام شاخه و نسخهٔ فریم‌ور را نشان بدهد. عدد تصویر/ثانیه،
نرخ تولید/نمایش جفت تصویر در مرورگر است؛ سنجش سرعت برد ESP32 نیست.

| کنترل | کاربرد |
|---|---|
| نوازش | ورودی مجازی PET و اجرای واکنش اصلی |
| غذای اول / غذای دوم | شبیه‌سازی دو تگ FOOD |
| خواب / بیداری | تغییر حضور تگ مجازی SLEEP؛ دوباره‌زدن، تگ را حذف می‌کند |
| مکث / ادامه | توقف و ادامهٔ زمان اجرای پیش‌نمایش |
| حرکت‌ها و پیش‌نمایش‌ها | پلک، نگاه، چشمک، لبخند، دعوت به بازی و تگ ناشناس |
| نمایش گرسنگی / درخواست نوازش | پیش‌نمایش مستقل ۱۰ثانیه‌ای؛ بدون افزودن امتیاز یا مصرف سهم Stage |
| چاپ وضعیت | افزودن وضعیت Demo به بخش «خروجی فریم‌ور» |

از دکمه‌ها استفاده کن؛ کلیدهای Serial نوشته‌شده در README اصلی میان‌بر صفحهٔ
وب نیستند. هنگام مخفی‌شدن تب هم زمان پیش‌نمایش مکث می‌کند؛ بازگشت به تب، مکث
دستی را لغو نمی‌کند.

پیشرفت در `localStorage` مرورگر، جدا برای هر شاخه و آدرس/پورت ذخیره می‌شود.
Refresh الزاماً پیشرفت را پاک نمی‌کند. برای شروع از صفر، دادهٔ همین سایت را
پس از بستن تمام تب‌های پیش‌نمایش همان آدرس/پورت از تنظیمات مرورگر پاک کن و
سپس آدرس پیش‌نمایش را دوباره باز کن؛ این کار داده‌های دیگر شاخه‌ها در همان
آدرس را نیز پاک می‌کند. دادهٔ وب به NVS برد یا Wokwi دسترسی ندارد. برای مقایسهٔ دو checkout
هم‌زمان، سرور دوم را با `--port 8788` اجرا کن؛ پورت دیگر ذخیره‌سازی جدا دارد.

## تغییر چشم‌ها با C++

همهٔ مسیرهای منبع زیر نسبت به روت ریپو هستند:

| فایل | برای چه تغییری؟ |
|---|---|
| [Eyes.cpp](../../firmware/tando_final_demo_15min/Eyes.cpp) | رسم، شکل و حرکت چشم‌ها |
| [Reactions.cpp](../../firmware/tando_final_demo_15min/Reactions.cpp) | واکنش‌ها و اولویت آن‌ها |
| [CareRequests.cpp](../../firmware/tando_final_demo_15min/CareRequests.cpp) | زمان‌بندی درخواست‌های مراقبت |
| [Demo.cpp](../../firmware/tando_final_demo_15min/Demo.cpp) | زمان Demo، Stage و پیشرفت |
| [TandoConfig.h](../../firmware/tando_final_demo_15min/TandoConfig.h) | ثابت‌ها و تنظیمات مشترک |

تغییر را در همین فایل‌های اصلی روی شاخهٔ آزمایشی انجام بده. `adapters/` و
`wrapper.cpp` فقط امکانات سخت‌افزاری را به مرورگر متصل می‌کنند؛ رفتار تندو را
در آن‌ها پیاده نکن. تغییر تنظیم مشترک ممکن است روی برد هم اثر داشته باشد.

سرور را در ترمینال اول روشن نگه دار. پس از ذخیرهٔ تغییر C++، در ترمینال دوم
روت ریپو بساز؛ اگر مسیر SDK/GFX را با متغیر محیطی داده‌ای، در این ترمینال هم
آن‌ها را تنظیم کن:

```powershell
& .\simulator\wokwi\.venv\Scripts\python.exe .\simulator\web\build.py
```

برای Python مستقل از `py -3 .\simulator\web\build.py` استفاده کن؛ گزینه‌های
`--wasi-sdk` و `--gfx-dir` نیز مانند `run.py` قابل استفاده‌اند. پس از ساخت موفق،
صفحه را Refresh کن. تغییر C++ خودکار در صفحهٔ باز بارگذاری نمی‌شود.

پیش‌نمایش، هویت فایل‌های اصلی، آداپترها و فایل WASM را بررسی می‌کند. اگر ساخت
قدیمی باشد، درخواست بازسازی می‌دهد. شکست ساخت، آخرین خروجی موفق را جایگزین
نمی‌کند؛ اجرای خروجی قدیمی به‌عنوان نتیجهٔ تغییر جدید هم پذیرفته نمی‌شود.

خروجی‌ها در `.build/` تولید می‌شوند و وارد Git نمی‌شوند. کپی‌های C++ در این
پوشه فقط ورودی موقت کامپایل‌اند و باید با منبع اصلی یکسان باشند؛ آن‌ها را
ویرایش نکن. `manifest.json` هش منبع، شاخه و نسخهٔ فریم‌ور را ثبت می‌کند.

## شاخهٔ آزمایشی، رد و تأیید

ابتدا زیرساخت وب بازبینی و تأیید می‌شود. پس از تأیید این پایه، برای نمونهٔ
تغییر پلک می‌توان از شاخهٔ فعلی آزمایش جدا ساخت:

```powershell
git switch -c experiment/eyes-blink feature/web-preview
```

پس از ورود زیرساخت تأییدشده به `develop`، آزمایش‌های بعدی باید از `develop`
به‌روز آغاز شوند. با عوض‌شدن شاخه، دوباره بساز و Refresh کن تا کد و پروفایل
ذخیره‌سازی همان شاخه اجرا شوند.

- قبل از تأیید ظاهر و رفتار توسط مالک پروژه، PR ساخته نمی‌شود.
- کامیت برای نگهداری مراحل آزمایش مجاز است؛ کامیت، PR، مرج و Release چهار کار متفاوت‌اند.
- اگر آزمایش رد شد، تغییرات همان آزمایش را روی شاخهٔ خودش ذخیره و به پایهٔ
  تأییدشده برگرد؛ فقط نامناسب‌بودن یک آزمایش دلیل پاک‌کردن کار نامرتبط نیست.
- اگر نتیجه تأیید شد، ساخت ESP32 و بررسی‌های مربوط انجام می‌شود؛ سپس نسخه و
  مستندات نهایی هماهنگ و PR به `develop` ساخته می‌شود.
- Merge و انتشار Stable مرحله‌های جدا هستند و طبق تأیید مالک پروژه انجام می‌شوند.

مثلاً اگر فقط `Eyes.cpp` را آزمایش کرده‌ای، برای نگه‌داشتن نتیجه و برگشت به
پایهٔ فعلی زیرساخت، بدون ایجاد PR:

```powershell
git add -- firmware/tando_final_demo_15min/Eyes.cpp
git commit -m "experiment: checkpoint blink trial"
git switch feature/web-preview
```

اگر فایل‌های بیشتری تغییر کرده‌اند، فقط فایل‌های همان آزمایش را آگاهانه
ذخیره کن. این مثال برای دورریختن تغییرات ذخیره‌نشده نیست. لازم نیست شاخهٔ ردشده
را حذف یا تاریخچه را بازنویسی کنی. پس از برگشت نیز ساخت و Refresh لازم است.

## خروجی مستقل برای مشاهده

برای ساخت یک فایل HTML قابل ارسال، از روت ریپو اجرا کن:

```powershell
py -3 .\simulator\web\build.py --standalone "$env:TEMP\tando-preview.html"
```

می‌توان به‌جای `py -3` از Python نصب Wokwi نیز استفاده کرد. HTML تولیدشده،
کد WASM و رابط را در خود دارد؛ دریافت‌کننده برای مشاهدهٔ آن به ابزار کامپایل
نیاز ندارد. فایل را در مرورگر باز کن. اگر سیاست مرورگر بازکردن فایل محلی را
مسدود کرد، از مسیر سرور محلی بالا استفاده کن.

این فایل snapshot همان ساخت است؛ تغییر C++ پس از آن، فایل قبلی را به‌روز
نمی‌کند. خروجی تولیدشده را به‌عنوان منبع اصلی یا جایگزین ساخت برد وارد Git نکن.

## از پیش‌نمایش تا برد ESP32

انتقال دستی منطق از وب به برد نداریم؛ هر دو از همان پوشهٔ
`firmware/tando_final_demo_15min/` استفاده می‌کنند. پس از پذیرش تغییر، برای
ساخت و آپلود، [راهنمای برد در README اصلی](../../README.md#ساخت-و-آپلود) را دنبال کن.
در Arduino IDE فایل `tando_final_demo_15min.ino` را با **تمام فایل‌های `.cpp` و
`.h` کنارش** باز کن، کتابخانه‌ها و برد/Port واقعی را انتخاب و Verify/Upload کن.
فایل `.wasm` یا HTML روی ESP32 آپلود نمی‌شود.

ماژول‌های رفتار و رسم اصلی، همراه نقطهٔ ورود در وب اجرا می‌شوند. ورودی‌های
لمس و RFID مجازی‌اند؛ کد دریافت فیزیکی Touch و RFID در وب اجرا نمی‌شود.
نمایشگر، دو بافر RGB565 مستقیم دارد و هدف پیش‌نمایش ۱۶ میلی‌ثانیه است؛ نرخ واقعی
به مرورگر و سیستم وابسته است.

وب زمان اجرای دستورهای ESP32، SPI/DMA، حساسیت سنسورها، برق و اتمی‌بودن نوشتن
Flash را شبیه‌سازی نمی‌کند. دیدن نتیجهٔ وب، کامپایل برد و تست سخت‌افزاری سه نوع
بررسی جدا هستند. چهار ایراد شناخته‌شدهٔ فریم‌ور با افزودن این ابزار رفع نمی‌شوند.

## رفع خطاهای رایج

| نشانه | اقدام |
|---|---|
| `invalid reference: feature/web-preview` | مراحل دریافت شاخه، شامل `remote set-branches --add` و `fetch` را اجرا کن. |
| `can't open file ... run.py` | شاخه را با `git branch --show-current` بررسی کن و فرمان را از روت ریپو بزن. |
| WASI SDK پیدا نشد یا ناقص است | مسیر پوشهٔ حاوی `bin/clang++(.exe)` و `share/wasi-sysroot` را با `--wasi-sdk` بده. |
| GFX پیدا نشد یا `SHA-256 mismatch` | منبع بدون تغییر نسخهٔ دقیق 1.13.0 را با `--gfx-dir` معرفی کن؛ بررسی هش را حذف نکن. |
| `Source changed`، `Branch changed` یا درخواست بازسازی | `build.py` را اجرا و پس از موفقیت Refresh کن. |
| پورت 8787 مشغول است | سرور قبلی خودت را با `Ctrl+C` ببند یا `run.py --port 8788` اجرا کن. |
| صفحه باز نشده یا دکمه‌ها فعال نیستند | آدرس چاپ‌شده، ترمینال ساخت و پیام خطای خود صفحه را بررسی کن؛ اول باید ساخت موفق شود. |
| `GET /favicon.ico` با 404 | فقط آیکون زبانه پیدا نشده؛ به‌تنهایی مانع اجرای پیش‌نمایش نیست. |

## بررسی‌های توسعه

از روت ریپو، با پیش‌نیازهای ساخت آماده:

```bash
python3 -m unittest discover -s simulator/web/tests -p 'test_*.py' -v
python3 simulator/web/build.py
node simulator/web/tests/selfcheck.mjs
```

در ویندوز به‌جای `python3` از `py -3` یا مسیر Python نصب Wokwi استفاده کن.
Node 22 یا جدیدتر فقط برای این selfcheck توسعه لازم است؛ کاربر پیش‌نمایش
به آن نیاز ندارد.

بررسی واقعی رابط مرورگر نیز اختیاری است. در محیط توسعه با نصب Playwright و
Chromium و روشن‌بودن سرور پیش‌نمایش:

```bash
python3 -m pip install playwright
python3 -m playwright install chromium
python3 simulator/web/tests/browser_check.py
```

این بررسی، نمایش دو چشم، نوازش، ذخیره و جداسازی پیشرفت شاخه‌ها، مکث، اندازهٔ
موبایل و ردکردن WASM ناسازگار را کنترل می‌کند. نتیجه و تصویرها در `.reports/`
ذخیره می‌شوند. این وابستگی‌ها فقط برای بررسی اختیاری توسعه‌اند.
