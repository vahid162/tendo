# پیش‌نمایش وب تندو

این مسیر برای طراحی حرکت، ظاهر و واکنش چشم‌هاست. همان فایل‌های C++ اصلی در
`firmware/tando_final_demo_15min/` با WebAssembly اجرا می‌شوند. منطق چشم‌ها،
Demo و واکنش‌ها در JavaScript بازنویسی نشده است.

## اجرای ویندوز

در PowerShell روت ریپو اجرا کن:

```powershell
& .\simulator\wokwi\.venv\Scripts\python.exe .\simulator\web\run.py
```

اگر از قبل Python روی سیستم داری، این فرمان هم قابل استفاده است:

```powershell
py -3 .\simulator\web\run.py
```

فرمان، C++ را می‌سازد و مرورگر را در `http://127.0.0.1:8787/` باز می‌کند.
ترمینال باز بماند؛ `Ctrl+C` سرور را متوقف می‌کند. استفاده از Python نصب‌شدهٔ
Wokwi فقط برای اجرای ابزار استاندارد Python است؛ هیچ بسته، تنظیم یا فایلی در
مسیر Wokwi تغییر نمی‌کند.

ساخت به Python 3.9 یا جدیدتر، WASI SDK و Adafruit GFX 1.13.0 نیاز دارد. ابزار
آن‌ها را از نصب موجود پیدا می‌کند و چیزی دانلود یا نصب نمی‌کند. نصب فعلی
Wokwi معمولاً SDK را در `$env:USERPROFILE\.wokwi\wasi-sdk` و GFX را در
`simulator/wokwi/.pio/libdeps/tando-s3-sim/Adafruit GFX Library` دارد.
در صورت نیاز مسیرها را صریح بده:

```powershell
py -3 .\simulator\web\run.py --wasi-sdk 'C:\tools\wasi-sdk' --gfx-dir 'C:\libraries\Adafruit GFX Library'
```

در لینوکس و macOS نیز `python3 simulator/web/run.py` با همین گزینه‌ها اجرا
می‌شود. متغیرهای `WASI_SDK_PATH` و `TANDO_WEB_GFX_DIR` هم پشتیبانی می‌شوند.

## تغییر چشم‌ها با C++

کد رسم و حرکت در `Eyes.cpp`، واکنش‌ها در `Reactions.cpp`، زمان‌بندی درخواست‌ها
در `CareRequests.cpp` و پیشرفت Demo در `Demo.cpp` قرار دارد. فایل‌های داخل
`adapters/` فقط امکانات Arduino و نمایشگر را به مرورگر متصل می‌کنند؛ رفتار
تندو را در آن‌ها پیاده نکن.

پس از تغییر C++، در ترمینال دوم روت ریپو بساز:

```powershell
& .\simulator\wokwi\.venv\Scripts\python.exe .\simulator\web\build.py
```

بعد صفحهٔ مرورگر را Refresh کن. پیش‌نمایش، هویت فایل‌های اصلی، آداپترها و
فایل WASM را بررسی می‌کند. اگر ساخت قدیمی باشد، درخواست بازسازی می‌دهد.
شکست ساخت، آخرین خروجی موفق را جایگزین نمی‌کند.

خروجی‌ها در `.build/` تولید می‌شوند و وارد Git نمی‌شوند. کپی‌های C++ در این
پوشه فقط ورودی تولیدشدهٔ کامپایل هستند و باید با منبع اصلی یکسان باشند؛
آن‌ها را ویرایش نکن. `manifest.json` هش منبع و نسخهٔ فریم‌ور را ثبت می‌کند.

## روند آزمایش و تأیید

ابتدا زیرساخت وب بازبینی و تأیید می‌شود. پس از ورود نسخهٔ تأییدشده به
`develop`، هر تغییر چشم روی شاخهٔ مستقلی مثل `experiment/eyes-blink` آغاز
می‌شود. وب، کد همان شاخه را اجرا می‌کند و نام شاخه را نشان می‌دهد.

- قبل از تأیید ظاهر و رفتار توسط مالک پروژه، PR ساخته نمی‌شود.
- کامیت محلی برای نگهداری مراحل آزمایش مجاز است؛ کامیت با PR و Release فرق دارد.
- اگر آزمایش رد شد، به شاخهٔ تأییدشده برمی‌گردیم. فقط تغییرات همان آزمایش کنار
  گذاشته می‌شوند؛ فایل‌های نامرتبط یا کار ذخیره‌نشدهٔ کاربر پاک نمی‌شوند.
- اگر نتیجه تأیید شد، ساخت ESP32 و بررسی‌های مربوط انجام می‌شود؛ سپس نسخه و
  مستندات نهایی هماهنگ و PR به `develop` ساخته می‌شود.
- Merge و انتشار Stable مرحله‌های جدا هستند و طبق تأیید مالک پروژه انجام می‌شوند.

داده‌های پیشرفت هر شاخه در مرورگر جدا ذخیره می‌شوند و به NVS برد دسترسی ندارند.
برای مقایسهٔ هم‌زمان دو checkout می‌توان سرور دوم را با `--port 8788` اجرا کرد.

## خروجی مستقل برای مشاهده

برای ساخت یک فایل HTML قابل ارسال، از گزینهٔ خروجی مستقل استفاده کن:

```powershell
py -3 .\simulator\web\build.py --standalone "$env:TEMP\tando-preview.html"
```

این فایل snapshot همان ساخت است؛ تغییر C++ پس از آن، فایل قبلی را به‌روز
نمی‌کند. خروجی تولیدشده را به‌عنوان منبع اصلی یا جایگزین ساخت برد وارد Git نکن.

## مرز پیش‌نمایش

ماژول‌های رفتار و رسم اصلی، همراه نقطهٔ ورود اجرا می‌شوند. ورودی‌های لمس و
RFID با فرمان‌های مجازی فعال می‌شوند؛ کد دریافت فیزیکی Touch و RFID در وب
اجرا نمی‌شود. نمایشگر، دو بافر RGB565 مستقیم دارد و هدف پیش‌نمایش ۱۶ میلی‌ثانیه
است. نرخ واقعی به مرورگر و سیستم وابسته است.

وب زمان اجرای دستورهای ESP32، SPI/DMA، حساسیت سنسورها، برق و اتمی‌بودن نوشتن
Flash را شبیه‌سازی نمی‌کند. چهار ایراد شناخته‌شدهٔ فریم‌ور با افزودن این ابزار
رفع نمی‌شوند. Wokwi و تنظیمات VS Code مستقل باقی می‌مانند.

## بررسی‌های توسعه

```bash
python3 -m unittest discover -s simulator/web/tests -p 'test_*.py' -v
python3 simulator/web/build.py
node simulator/web/tests/selfcheck.mjs
```

Node فقط برای بررسی خودکار توسعه لازم است؛ کاربر پیش‌نمایش به آن نیاز ندارد.

بررسی واقعی رابط مرورگر نیز برای توسعه قابل اجراست. با نصب Playwright و
Chromium در محیط توسعه و روشن‌بودن سرور پیش‌نمایش:

```bash
python3 simulator/web/tests/browser_check.py
```

این بررسی، نمایش دو چشم، نوازش، ذخیره و جداسازی پیشرفت شاخه‌ها، مکث، اندازهٔ
موبایل و ردکردن WASM ناسازگار را کنترل می‌کند. نتیجه و تصویرها در `.reports/`
ذخیره می‌شوند. نصب Playwright فقط برای این بررسی اختیاری است و برای اجرای
پیش‌نمایش لازم نیست.
